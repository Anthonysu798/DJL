# DJL native computer-use helper

Original Swift/AppKit helper with bundle identity `com.djl.computer-use`. The Electron manager owns the private stdin/stdout channel, authenticated thread identity, action history, screenshots' persisted lifecycle, and agent authorization. This helper does not connect to or reuse the OpenAI helper.

## Build and protocol smoke

From the repository root:

```bash
bash apps/desktop/native/computer-use/build.sh arm64
python3 apps/desktop/native/computer-use/protocol-smoke.py
printf '%s\n' '{"id":"status","threadId":"native-smoke","request":{"method":"status"}}' | 'apps/desktop/native/computer-use/.build/DJL Computer Use.app/Contents/MacOS/DJLComputerUse'
file -b 'apps/desktop/native/computer-use/.build/DJL Computer Use.app/Contents/MacOS/DJLComputerUse'
codesign --verify --strict --verbose=2 'apps/desktop/native/computer-use/.build/DJL Computer Use.app'
```

Requires Xcode command-line tools; uses the installed Swift compiler in Swift 5 language mode and a macOS 14.4 deployment target. `build.sh x86_64` cross-compiles an Intel executable. Set `DJL_COMPUTER_USE_BUILD_DIR` to change output (default `.build/`, ignored). Builds are ad-hoc signed for development; production packaging must sign the stable nested bundle with DJL's real signing identity before the outer app is signed. Building is separate from notarization and runtime verification.

One JSON object per line, maximum input 256 KiB. Envelope:

```json
{ "id": "request-1", "threadId": "authenticated-host-thread", "request": { "method": "status" } }
```

Replies are `{"id":"request-1","response":{"method":"status","result":{...}}}` or the contract's typed error. Session Stop emits `{"event":{"type":"stopped","sessionId":"..."}}`. The direct human floating-window Stop revokes the entire owning thread and additionally emits `{"event":{"type":"thread-stopped","threadId":"..."}}`; the manager holds that thread stopped until trusted turn start. Stdout contains only protocol JSON. Request/response shapes are defined in `packages/contracts/src/computerUse.ts`; unknown fields are rejected. The host must never expose the private stdin pipe or accept a model-supplied thread ID.

## Implemented boundaries

- `status` checks `AXIsProcessTrusted` and `CGPreflightScreenCaptureAccess` without prompting. Permission flags reflect this helper's own identity, not the Electron host's identity.
- Only the explicit renderer-originated `permissions.request` method invokes a system permission prompt, with `permission` set to `accessibility` or `screenRecording`. The manager must reject this method from agent HTTP calls. It is deliberately absent from smoke tests.
- `apps.list` enumerates running bundle identities and ordinary CoreGraphics windows. It does not launch apps or capture the desktop.
- Sessions bind thread, bundle ID, PID, mandatory libproc process start seconds/microseconds and canonical executable path, and CG window ID. Every operation revalidates identity. Idle sessions expire after 30 minutes. Targets must already exist; there is no application launch/activation method.
- AX matching uses a unique window number, or a unique title/bounds match. Ambiguity fails. Observations are bounded to 500 nodes, 30 levels and approximately five seconds plus the current bounded AX call. Secure/protected elements omit labels/values/children/references. Element IDs belong to one snapshot and are revoked by actions and Stop. Elements must still belong to the bound AX window when used.
- Screenshots use `SCContentFilter(desktopIndependentWindow:)` plus `SCScreenshotManager` for the exact requested PID/window. No full-display capture fallback. Inline PNGs are capped at 3 MB raw / 4 MB base64 and 2048 pixels along the longest dimension.
- AX `setValue`, supported AX actions, and element left-click via AXPress are dispatched only to the bound process/window. AXRaise is explicitly rejected. A target currently in the foreground is rejected for background actions. A shared HID-counter guard accepts newly attributed human pointer/focus activity and rejects unattributed changes or target OS-foreground ownership. This does not establish WindowServer keyboard isolation; the later CPS audit below keeps raw input disabled.
- Coordinate clicks, drag, Unicode typing, named keys and scroll have process-directed `CGEvent.postToPid` implementations. They are **disabled by default** until controlled fixture verification proves target effects and human-state preservation. Setting `DJL_COMPUTER_USE_EXPERIMENTAL_INPUT=1` enables experimental dispatch for deliberate fixture testing; this is not proof of background compatibility. No global event posting, cursor warp, OS-foreground activation or silent foreground fallback exists. The disabled raw experiment temporarily posts app-local activation/deactivation notifications; the CPS audit below found that this steals actual keyboard focus, so it is unsafe outside owned fixtures until protection is verified. Keyboard input requires a prevalidated focused AX element and rechecks it before each chunk; app-local focus alone is insufficient to establish safe keyboard ownership. Named key support is limited to navigation/editing keys; Unicode belongs in `type`.
- Results acknowledge dispatch with `effect: "unverified"`; observe the actual target again to establish effects. Neither an AX success code nor event delivery establishes a successful interaction.
- A nonactivating floating panel displays the selected target, a live five-frame-per-second exact-window ScreenCaptureKit preview when Screen Recording is granted, a screenshot when observed, and a direct Stop button. Closing hides it; another observation restores it. A separate noninteractive panel draws an original orange vector arrow and pulse, interpolates movement over 120 ms, and respects Reduce Motion without moving the physical cursor. The helper does not activate DJL or the target to show these panels.
- Actions are serialized; Stop bypasses the worker, marks cancellation immediately, revokes references and cancels pending opens via per-thread epochs. No-session Stop covers only that thread. Drag checks cancellation between steps and posts its release in `defer`; key and click down/up events are paired. EOF/SIGTERM/SIGINT revoke work and allow posted events to release before exit. SIGKILL cannot run cleanup.
- Queue size is capped at 64, queue age at 15 seconds, AX messaging at 0.2–0.4 seconds per element, screenshot waiting at five seconds, and drag duration at ten seconds. At most 100 sessions and 1000 thread epoch records exist per helper lifetime. Native `history.*` remains unsupported. `activity.capture` is a private manager-only primitive used by the opt-in passive recorder; public renderer/agent callers must not reach it. `passiveHistory` advertises this implemented capture primitive, not consent or active recording. App/domain/privacy policy preflight runs before the second static-label pass; capture reads are cancellation-aware and thread Stop revokes queued recorder captures. No screenshots or editable values enter passive snapshots.

## Verified product input path (experimental gate retained pending integration review)

The helper now implements the independently verified window-local setter and window field 51. Each raw operation validates its arguments and bound target before temporary focus. The gated experiment uses AXFrontmost to distinguish app-local state: an explicitly false state is temporarily seeded with target-only AppKit13/1 and restored with13/2; an already true state is borrowed without activation/deactivation; unknown state is unsupported. This state is insufficient to determine real keyboard ownership. The later CPS audit invalidates treating a pre-existing true state as safe background ownership, and the gate remains off. It never deactivates a target the human has made OS foreground. Process identity and window/human state are checked between steps and again after blocking AX validation.

Keyboard input requires a fresh enabled/editable/nonsecure focused-element identity before seeding, with the same window and secure-ancestor checks before every Unicode chunk. A target focus change stops further chunks and revokes the session. Paired releases precede focus cleanup. Cleanup retries are bounded; failure remains an explicit error even after Stop, revokes the session, and quarantines the PID/start/executable identity against later sessions. Only observed inactive state, genuine human OS foreground ownership or process replacement clears that quarantine.
