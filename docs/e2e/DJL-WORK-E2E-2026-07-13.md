# DJL Work end-to-end report — 2026-07-13

## Release decision

The implemented DJL Work core passes its automated suite, desktop build/package checks, and the primary real-Electron workflows. Twenty of the 24 required desktop scenarios have visible UI evidence. One stream-interruption scenario is partial, and three OCR-provider scenarios are blocked by external production assets or credentials.

**Full production release remains blocked.** The repository does not contain a signed PaddleOCR/PP-Structure sidecar distribution, Google/Azure staging integrations, the pinned E5-small ONNX runtime, or Apple Developer ID signing/notarization. The package produced here is suitable for continued internal validation, not public distribution.

## Defects found and fixed during desktop validation

1. Managed Work folder creation raced first-turn title generation. The folder is now created before provider startup/title generation.
2. Retry could replay provider events into duplicate transitions. Deterministic command IDs and replay handling now keep lifecycle changes idempotent.
3. Prepared-document rows could crowd the transcript/composer. The Work panel now bounds overflow and uses a collapsed prepared-document section.
4. OCR preparation failures lost their typed Needs input condition. Typed OCR failures are now preserved through the queue boundary.
5. Restart-orphaned Working tasks could remain stuck. Startup reconciliation now cancels orphaned work and exposes Retry.
6. Recoverable preparation jobs were reconciled as dead work, and the PubSub handoff could lose recovered jobs. Recovery ordering and a persisted queue now resume and dispatch them safely.
7. Raw DeepSeek tool protocol markup could leak into task titles. Title output is sanitized at the trust boundary and falls back to the user prompt.
8. Desktop smoke tests inherited user state and left Electron descendants alive. The harness now uses isolated HOME/state/profile/ports and terminates the complete process group.

## Remaining production blockers

1. Build, sign, publish, verify, repair, and uninstall platform-specific PaddleOCR PP-OCRv6 Medium plus PP-StructureV3 sidecar artifacts and their manifest.
2. Implement and validate Google Document AI and Azure Document Intelligence adapters with staging credentials, secret-store handling, explicit consent, and administrator policy.
3. Replace the deterministic semantic fallback with the pinned multilingual E5-small ONNX model and validate portable in-process inference and index rebuilds.
4. Sign and notarize the macOS app with the final DJL bundle identity; the current package is ad hoc signed as Electron.
5. Perform a direct UI-observed provider network interruption/reconnect run to close scenario 17.

No code-only workaround can truthfully close the first four items without the missing artifacts, accounts/credentials, model binary, and Apple signing identity.
